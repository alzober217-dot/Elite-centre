# مركز النخبة

واجهة عربية RTL لاختيار الصفوف والمواد، مع الأسعار وأسماء المدرسين. بيانات الكتالوج في `server/catalog.json`، والبوت يحدّث الملف نفسه حتى تظهر التغييرات في الموقع.

## التثبيت والتشغيل

```sh
npm install
npm run server
```

في طرفية ثانية:

```sh
npm run dev
```

افتح عنوان Vite الذي يظهر في الطرفية. مع إعدادات `.env.example` يعمل API محلياً على `http://127.0.0.1:3001`؛ يقرأ المنفذ من `API_PORT` أو `PORT` والعنوان من `API_HOST`. يمرر Vite طلبات `/api` إلى المنفذ نفسه. للوصول من الهاتف على الشبكة نفسها استخدم `npm run dev -- --host 0.0.0.0`.

## النشر على Render

ملف `render.yaml` يجهز خدمة Node.js للـAPI والبوت باسم `elite-center-api` مع فحص صحة على `/api/health` وقرص دائم بسعة 1 GB على `/var/data`. أنشئ Blueprint جديداً في Render واربطه بمستودع المشروع، ثم أدخل المتغيرات المطلوبة عند الطلب:

- `TELEGRAM_BOT_TOKEN`: رمز البوت من BotFather؛ يبقى في إعدادات Render ولا يُحفظ في المستودع.
- `TELEGRAM_BOT_USERNAME`: اسم البوت من دون `@`.
- `TELEGRAM_ADMIN_IDS`: أرقام حسابات المدراء مفصولة بفواصل. استخرج الرقم من البوت باستخدام `/myid`.
- `CORS_ORIGINS`: أصول واجهة الويب المسموح لها باستدعاء API، مفصولة بفواصل ومن دون مسارات، مثل `https://example.com`. لا يلزم إضافة أصل تطبيق Capacitor؛ فهو مسموح به مسبقاً.

الخدمة تستمع على منفذ Render وعلى `0.0.0.0`. أدخل أرقام المدراء عند إنشاء Blueprint؛ في أول تشغيل ينسخ الخادم `server/catalog.json` إلى القرص إن لم يكن موجوداً، وينشئ `permissions.json` من `TELEGRAM_ADMIN_IDS` من دون استبدال الملفات الموجودة. بقية سجلات الطلاب والطلبات والجلسات والصور تحفظ في `/var/data` وتبقى عبر إعادة النشر بفضل القرص الدائم. الكتالوج ينسخ مرة واحدة فقط؛ بعد ذلك تعديلات البوت على القرص هي المعتمدة، ولن يستبدلها نشر جديد بملف Git. يتطلب القرص الدائم خطة Render مدفوعة؛ لا تحذف القرص ولا تنشئ قرصاً جديداً عند إعادة النشر. أبقِ الخدمة على نسخة واحدة، وأوقف polling المحلي للبوت عند تشغيله على Render، لأن ملفات JSON وTelegram polling غير معدة للتشغيل المتعدد.

عنوان الخدمة المنشور هو API فقط، وليس استضافة لواجهة React. بعد النشر استخدم عنوان Render في `VITE_API_BASE_URL` عند بناء الواجهة أو APK، مثلاً `https://elite-center-api.onrender.com`، ثم أعد بناء التطبيق. إذا استضفت واجهة الويب على نطاق منفصل، أضف أصلها إلى `CORS_ORIGINS` ثم أعد النشر.

بيانات المشروع المحلية الحساسة مستثناة من Git، لذلك لا تنتقل تلقائياً إلى Render. إذا كانت لديك طلبات أو اشتراكات قائمة، صدّر نسخة احتياطية وانقل ملفات JSON المطلوبة إلى القرص الدائم بأداة نقل آمنة قبل اعتماد الخدمة للطلاب؛ لا ترفعها إلى المستودع أو إلى محادثة عامة. تحقق بعد النشر من `/api/health` ثم `/api/catalog`، واختبر تسجيل الدخول والبوت قبل تحويل المستخدمين.

## إعداد تيليغرام

انسخ أسماء المتغيرات من `.env.example` إلى ملف `.env` محلي، ثم أضف token البوت إلى `TELEGRAM_BOT_TOKEN`. لا تضع token في ملفات JavaScript أو Git.
يعمل polling افتراضياً؛ اضبط `TELEGRAM_BOT_POLLING=false` لتشغيل API محلياً دون الاتصال بتيليغرام.
لإتاحة ربط الطالب وتسليم كود الدخول بعد الموافقة، عيّن `TELEGRAM_BOT_USERNAME` إلى اسم البوت دون `@` مع تشغيل polling وإعداد `TELEGRAM_BOT_TOKEN`. عند إرسال طلب التسجيل يظهر للطالب رابط أحادي الاستخدام صالح لمدة 15 دقيقة؛ بعد فتحه في المحادثة الخاصة يحفظ الخادم Telegram user ID للطلب. عند الموافقة يُرسل الرمز إلى المحادثة ويسجل الخادم نتيجة التسليم. إذا لم يربط الطالب حسابه أو تعذّر تأكيد الإرسال، يظهر الرمز للمراجع مرة واحدة لإرساله يدوياً. لا تُظهر حالة الإرسال نجاحاً قبل تأكيد Telegram.

1. شغّل البوت وأرسل `/myid` إليه.
2. أضف رقم حسابك كنص داخل `telegramAdminIds` في `server/permissions.json`.
3. أعد تشغيل `npm run server`.

استخدم البوت في محادثة خاصة. أرسل `/start` أو `/menu` من حساب إداري مصرح لفتح لوحة الأزرار. منها تُدار الصفوف والمواد والأسعار والمدرسون والأخبار العامة وإعلانات الإدارة والإشراف على موجز الطلاب والأكواد وطلبات التسجيل واستيراد العلامات. أكواد الدخول عشوائية ومجزأة في التخزين؛ تُرسل للطالب المرتبط عند تأكيد Telegram، وإلا يعرض البوت الكود الجديد للمراجع مرة واحدة في تدفق الإصدار. يمكن استخدام `/newcode <email> | <student name> | <grade>` لإنشاء كود جديد، و`/studentids 1` لعرض معرّفات الطلاب النشطين اللازمة لملف العلامات، و`/marks` لإرشادات الاستيراد. التعديل يطلب القيمة الجديدة برسالة، والحذف يحتاج تأكيداً. أرسل `/cancel` لإلغاء العملية.

أوامر الإدارة محصورة بأرقام `telegramAdminIds` في `server/permissions.json`. عند ضبط `TELEGRAM_BOT_TOKEN` يصل للمدراء تنبيه بطلب تسجيل جديد.

## البيانات والوسائط

بيانات الطلاب والأكواد وصلاحيات المدراء والجلسات تحفظ محلياً في ملفات JSON تحت `server/`، وهذه الملفات مستثناة من الإضافات الجديدة إلى Git. يبقى ملف الدورات الرقمية القديم وحقله في الكتالوج محفوظين كبيانات تاريخية، لكنهما لم يعودا يظهران في الواجهة أو API أو أدوات البوت؛ لا تحذفهما يدوياً دون مراجعة/ترحيل مستقل. إذا كانت ملفات البيانات قد أُضيفت إلى Git سابقاً، يجب إزالتها من التتبع ومراجعة تاريخ المستودع؛ `.gitignore` لا يحذف الملفات المتتبعة أو نسخها السابقة.

يُرسل الطالب طلباً يتضمن اسمه وهاتفه وبريده وصفه والمواد الدراسية المختارة. عند توفر إعدادات البوت ينشئ الخادم رابط ربط عشوائياً أحادي الاستخدام صالحاً لمدة 15 دقيقة؛ يخزن بصمته فقط، ويتحقق من استخدامه في محادثة خاصة قبل ربط Telegram user ID بالطلب. عند القبول ينشئ البوت كوداً عشوائياً مرتبطاً بالبريد ويحفظ تجزئته فقط في ملف الاشتراكات، ثم يرسل الكود للحساب المرتبط ويسجل حالة التسليم دون حفظ نصه. عند عدم الربط أو عدم تأكيد التسليم يظهر الكود للمراجع مرة واحدة لإرساله يدوياً. يسجل الطالب الدخول بالبريد والكود، وتستمر جلسة الوصول ست ساعات.

جلسات المتصفح تستخدم Cookie من نوع `HttpOnly` و`SameSite=Lax`؛ جلسات الويب تُحفظ في `server/student-sessions.json` كمعرّفات مجزأة ولا تحفظ رمز الجلسة الصريح. يجب حفظ ملفات `server/` الحساسة في تخزين محمي ونسخها احتياطياً. عند تشغيل الخادم خلف reverse proxy HTTPS مضبوط وموثوق فقط، اضبط `TRUST_PROXY=true` حتى يضيف الخادم وسم `Secure` إلى Cookie. تطبيق Capacitor يستخدم Bearer token محلياً لأن Cookie HttpOnly عبر أصل التطبيق الأصلي غير ملائمة؛ لا تشارك جهازاً غير موثوق، وتسجيل الخروج يبطل الرمز من الخادم.

تستخدم المنصات الأصلية `@aparajita/capacitor-secure-storage` (iOS Keychain وAndroid Keystore مع تخزين مشفر)، ولا تحفظ رمز الجلسة في `localStorage`. يهاجر التطبيق الرمز المحلي القديم إلى التخزين الآمن عند بدء التشغيل ويحذفه من `localStorage` بعد نجاح الترحيل. تعطيل مزامنة iCloud واختيار `whenUnlockedThisDeviceOnly` يمنعان نقل الرمز بين الأجهزة. إعداد Capacitor ومجلد `android/` موجودان؛ أعد `npm run android:sync` بعد أي تغيير للواجهة أو الإضافات.

يحفظ `community-data.json` بيانات موجز الطلاب والتعليقات والتفاعلات والمحفوظات والبلاغات وإعلانات الإدارة والإشعارات والعلامات وسجل الاستيراد. تُكتب تحديثاته ذرياً مع نسخة احتياطية سابقة باسم `community-data.json.bak`. شغّل نسخة واحدة فقط من الخادم على مجلد البيانات؛ ملفات JSON ليست مخزناً مشتركاً متعدد النسخ.

### موجز الطلاب وإعلانات الإدارة

الموجز خاص بالجلسات النشطة، والنشر النصي محدود بـ2000 حرف. يمكن للطلاب التعليق والتفاعل والحفظ والإبلاغ؛ البلاغ الواحد لكل طالب/منشور لا يتكرر. يراجع المدير البلاغ من لوحة البوت `/reports`، ويعاين المنشور قبل إخفائه أو إغلاق البلاغ. الأخبار المنشورة على الموقع تبقى عامة، أما إعلانات الإدارة فتُنشر من لوحة البوت بعد معاينة وتأكيد، وتظهر في مساحة الطالب منفصلة مع حالة مقروء/غير مقروء؛ يمكن أرشفتها من إدارة الإعلانات. جميع عمليات حفظ المجتمع والنتائج تستخدم كتابة ملف ذرياً ونسخة `.bak`.

### ملف Excel للعلامات

ارفع إلى البوت في محادثة خاصة ملف `.xlsx` لا يتجاوز 5 ميغابايت أو 5000 صف، من ورقة واحدة فقط. استخرج معرّفات الاشتراكات النشطة عبر `/studentids 1` (للتنقل بين الصفحات استخدم `/studentids 2` وما بعدها). يجب أن يكون صف العناوين والترتيب كما يلي حرفياً:

```text
student_id | subject | exam | term | score | max_score | date
```

تُقبل التواريخ بصيغة `YYYY-MM-DD` أو خلايا Excel ذات تنسيق تاريخ، والعلامة والأعلى منها أرقام. لا تُقبل الصيغ. يعرض البوت المعاينة على صفحات تشمل جميع الصفوف؛ لا يظهر زر التأكيد إلا بعد مراجعة كل الصفحات، ويظل التأكيد محجوباً عند وجود أخطاء. أي معرف مفقود/غير معروف/ملتبس أو صف مكرر يمنع الدفعة كاملة. عند التأكيد يستبدل السجل المطابق وفق (معرف الطالب، المادة، الاختبار، الفصل)، ويُحفظ سجل الدفعة مع بصمة الملف لمنع استيراد الملف نفسه مرتين. تظهر العلامات للطالب صاحب الاشتراك فقط، ويصل إشعار نشر إلى الطلاب المعنيين.

## تطبيق Android

يتطلب البناء المحلي Android Studio أو Android SDK مع Android Platform 36 وBuild Tools 36، إضافة إلى JDK 21. بعد إعداد الأدوات:

```powershell
npm ci
npm run android:sync
scripts\build-android.ps1
```

أُنشئ مشروع `android/` بالفعل، لذلك لا تكرر `android:add` إلا إذا حذفت المشروع عمداً. ينتج البناء ملف تثبيت تجريبياً في `android\app\build\outputs\apk\debug\app-debug.apk`. ثبّته يدوياً على الهاتف، أو وصّل جهازاً مصرحاً عبر USB وشغّل `scripts\install-android-device.ps1`. يتوفر أيضاً سير عمل GitHub Actions لبناء APK تجريبي يدوياً أو عند دفع وسم يبدأ بـ`android-v`.

قبل مزامنة إصدار للاستخدام الحقيقي، عيّن `VITE_API_BASE_URL` في `.env` المحلي إلى عنوان API عام يعمل عبر HTTPS. لا يمكن للهاتف الوصول إلى `127.0.0.1` على جهاز المطور كخادم الموقع، كما أن خادم التطوير المحلي ليس بديلاً عن API منشور. البناء الحالي ينتج APK تجريبياً غير موقّع للنشر في المتجر؛ يتطلب إصدار Google Play إعداد توقيع release. الإشعارات المحلية تعمل مع التنبيهات الجديدة أثناء فتح مساحة الطالب، أما إرسال push عند إغلاق التطبيق فيتطلب إعداد خدمة push خلفية.

## حدود النسخة الحالية

التسجيل يرسل طلباً للمراجعة؛ الكود يثبت صلاحية الاشتراك لكنه ليس نظام استعادة كلمة مرور أو هوية دائمة. لا يوجد دفع إلكتروني أو قاعدة بيانات إنتاجية؛ سجلات JSON مناسبة للتجربة المحلية فقط. توقيع إصدار Android للنشر وإعداد خدمة push الخلفية غير مكتملين.

## الفحوصات

```sh
npm run build
npm run lint
npm test
```

تعمل اختبارات API على مجلد بيانات مؤقت ومعزول، ولا تستخدم بيانات الطلاب المحلية أو ملف `.env`.

بيانات الصفوف والأسعار الحالية ابتدائية ويمكن تعديلها من البوت. يدعم التخزين الحالي مثيلاً واحداً للخادم وملفات بيانات محلية؛ انقل البيانات إلى مخزن مشترك قبل التوسع إلى عدة نسخ.
